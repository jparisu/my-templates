# Manual template validation

This directory contains the manual validator for the generated project template.

## Files

- [`validate_template.py`](/home/jparisu/projects/devs/my-templates/tests/manual/validate_template.py): copies the template, validates the generated project, writes reports, and removes the temporary copy.

## Usage

Run commands from the repository root:

```bash
python tests/manual/validate_template.py --help
python tests/manual/validate_template.py
python tests/manual/validate_template.py --project-name "My Validation Run"
python tests/manual/validate_template.py --keep-project
python tests/manual/validate_template.py --run lint --run pytest --pytest-target tests/test_import.py
```

The script exposes a small set of inputs:

- `--project-name`: the human-readable Copier project name. It defaults to `Template Validation`.
- `--keep-project`: keep the generated project after the run finishes.
- `--copy-only`: render the project without creating the virtualenv or running validations.
- `--run`: choose which validation groups to run. Available values are `precommit`, `lint`, `pytest`, `docs`, and `build`.
- `--pytest-target`: choose the pytest path or node id when `pytest` is selected. It defaults to `tests`.

Everything else uses the template defaults and the repository conventions.

In manual validation runs, the `precommit` selection skips the auto-fixing Ruff hooks. Ruff and mypy failures are reported through the `lint` step in check-only mode so the copied project is not silently modified before it gets deleted.

## What it does

The validator will:

- copy the local Copier template into an isolated workspace
- create a virtual environment inside the generated project
- install the generated project's development dependencies
- run checks through the generated project's `Makefile`
- run the selected validation pipeline
- write a short summary plus detailed reports
- remove the copied project unless `--keep-project` is set

## Reports and workspaces

By default the validator writes under the repository root:

- Reports: `.template-validation/reports/<run-id>/`
- Generated project workspace: `.template-validation/workspaces/<run-id>/`

Useful artifacts:

- `summary.txt`: concise pass/fail summary
- `report.md`: readable report with the main paths
- `report.json`: machine-readable details
- `logs/*.log`: full output for each executed step

Open `summary.txt` first. It is the quickest way to see whether the full validation succeeded and, if it failed, which step and log file to inspect.

Use `report.md` when you need the step-by-step detail: selected checks, cleanup status, working directories, exact commands, and log paths.

## Environment notes

The validator uses the `copier` CLI from your `PATH` and creates a project-local virtual environment inside the rendered project. This keeps linting, pytest, docs, and build checks aligned with the generated project's own dependencies instead of the template repository environment.

The script expects a local `python3.12` interpreter because that is the current default generated by the template. If that default changes in [`copier.yml`](/home/jparisu/projects/devs/my-templates/copier.yml), update `DEFAULT_PYTHON_VERSION` in [`validate_template.py`](/home/jparisu/projects/devs/my-templates/tests/manual/validate_template.py).
